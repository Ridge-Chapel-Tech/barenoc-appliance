**Version:** 0.1 (draft for review)
**Status:** Design — awaiting enrollment-plan approval
**Last Updated:** 2025-08-01

## 1. Overview & Goals

BareNOC gains **passwordless, passkey-first identity** via **Pocket ID**, a self-hosted OpenID Connect Certified™ + OAuth 2.0 provider (BSD 2-Clause license — permissive, safe for commercial bundling).

**Goals:**
1. Passkey login for admins and operators — no passwords, keys never leave the user's device.
2. Pocket ID as the identity source of truth **on the rack** (default for all deployments, zero-cloud consistent).
3. Simple onboarding: invite → enroll passkey → done.
4. Group-driven roles: Pocket ID groups map to BareNOC admin/operator/readonly.
5. Keep local accounts as the break-glass fallback.
6. **Device identity & authorization (Phase 2):** devices get passkey identity (agent-capable) and group-based access control; SNMP-only gear gets passkey-bound management; device groups are managed inside BareNOC and mirrored to Pocket ID.

**Non-goals (this phase):**
- Replacing local accounts entirely (fallback stays).
- Federating with external IdPs (customer could later point Pocket ID elsewhere; out of scope).

## 2. Architecture

```
┌────────────────── 10-inch rack ──────────────────────┐
│  nginx (443) ──► /api/* → api container              │
│      │                                              │
│      └──► /auth/pocket-id/* → pocket-id container    │
│                                                        │
│  pocket-id: OIDC provider (passkeys, groups, admin UI) │
│  api: FastAPI — OIDC client (authlib) + local accounts │
└────────────────────────────────────────────────────────┘
```

- **Pocket ID container** joins the Docker Compose stack (name `pocket-id`), its data in `/opt/barenoc/volumes/pocket-id/` (SQLite + uploaded assets) — **joins the Layer 1 backup scope**.
- **nginx** routes a dedicated path prefix to Pocket ID (keeps one origin: `https://<host>/auth/pocket-id/…`), so no extra port exposure — consistent with UFW (443 only).
- **BareNOC api** becomes the OIDC client (authorization code + PKCE), keeping its existing local JWT session model unchanged downstream.

> Note: verify exact image/port/env at implementation (`docker.io/stonith404/pocket-id`, internal port 8080 per upstream docs).

## 3. OIDC Integration Design

### Auth flow (BareNOC web UI)

1. User clicks **"Sign in with passkey"** on `/login`.
2. api redirects to Pocket ID `/authorize` (PKCE `code_challenge`, `state`, `nonce`).
3. User authenticates in Pocket ID with their passkey.
4. Pocket ID redirects to `https://<host>/api/v1/auth/oidc/callback?code=…&state=…`.
5. api exchanges code → tokens → fetches userinfo/claims (`sub`, `email`, `name`, `groups`).
6. **JIT provisioning:** api finds or creates the local `User` record (match by `email` first, else `oidc_sub`), sets role from group mapping, issues the existing JWT + cookie.
7. User lands on `/dashboard`. Downstream (tickets, audit, roles) unchanged.

### Claims → role mapping (configurable, env-backed)

| Pocket ID group | BareNOC role |
|-----------------|--------------|
| `barenoc-admins` | admin |
| `barenoc-operators` | operator |
| (any other / none) | readonly (least privilege) |

- Group names configurable via env (`OIDC_GROUP_ADMIN`, `OIDC_GROUP_OPERATOR`).
- User in multiple groups → highest role wins.
- `oidc_sub` column added to `users` for idempotent linking; email match used when available.

### Config surface

```
OIDC_ENABLED=true
OIDC_PROVIDER_URL=https://<host>/auth/pocket-id/     # discovery endpoint
OIDC_CLIENT_ID=barenoc
OIDC_CLIENT_SECRET=...
OIDC_GROUP_ADMIN=barenoc-admins
OIDC_GROUP_OPERATOR=barenoc-operators
```

- Registered in Pocket ID admin as a **Community Application** (client credentials generated by Pocket ID).
- Settings UI gains an **Identity & Passkeys** section: enable/disable, provider URL, client ID/secret (redacted), group mapping, plus a **"Open Pocket ID admin"** link and a **"Send test login"** path.

### Local accounts fallback

- Existing username/password login + forced-password-change stay functional and visible on `/login` ("Sign in with password").
- Built-in `admin` remains as break-glass. OIDC users get a random, unusable local password hash (no password exists to reset).

## 3b. Device Identity & Authorization (Phase 2 — decisions locked 2025-08-01)

### Capability split (honest)

| Device class | Identity | Management auth |
|---|---|---|
| **Agent-capable** (mini PCs, edge agents, rack compute) | Passkey enrolled into Pocket ID at onboarding; BareNOC verifies device by passkey-attested identity instead of shared secrets | Passkey-bound |
| **SNMP-only gear** (UniFi switches/APs/gateway) | Cannot hold a passkey (no WebAuthn) — keeps SNMP credentials (already Fernet-encrypted at rest) | **Passkey-bound human** (option a): only a passkey-authenticated admin may issue actions (reboot/patch/poll) against them |

### Authorization model

- **Device groups are managed inside BareNOC** (device detail/grouping UI) and **mirrored to Pocket ID as groups** (e.g., `device-core`, `device-edge`, per-site).
- Pocket ID group claim is checked **before every device action AND view/configure** — group membership = device authorization domain.
- Admin group membership decides which devices a user can view, configure, and act on.
- **Revocation:** disabling a device's passkey (or removing a user from a group) takes effect immediately — no shared-secret rotation needed for agent devices.

### Device onboarding flow (BareNOC-driven)

```
Add device in BareNOC → pick group (device-core / device-edge / …)
  ├─ agent-capable: device enrolls passkey (agent holds credential) → verified → live
  └─ SNMP gear: enters SNMP creds (encrypted) → marked managed — actions require
     passkey-authenticated admin (group checked)
Manage: admin passkey-login → group claim checked → view/configure/act on group's devices
Kick:   revoke device passkey (or remove from group) in Pocket ID → immediate
```

### Open item (deferred, not blocking)
- Per-device SNMPv3 keys issued/rotated through Pocket ID's API (option b) — noted for a future release.

## 4. Onboarding & Enrollment Flow (the plan to approve)

### A. Turnkey setup — us, at provisioning (~10–15 min, one-time)

1. Rack boots → `pocket-id` container comes up with the stack.
2. We run Pocket ID's first-run wizard and create the organization admin, enrolling a **vendor break-glass passkey** (stored in our password manager) so we can always recover the IdP during provisioning.
3. We create the three groups (`barenoc-admins`, `barenoc-operators`) and register the BareNOC community application (client ID/secret).
4. We add the OIDC config to `.env` and flip `OIDC_ENABLED=true`.
5. We invite the **customer's primary admin** by email; on first click they enroll their **own** passkey on their device. Done — that admin now has admin rights in BareNOC via the group.

### B. Customer admin adds a user (2 min)

1. From BareNOC **Settings → Identity & Passkeys → "Open Pocket ID admin"**.
2. **Invite user** (email) — optionally pre-assign the operator group.
3. User clicks the invite link → enters their name → **creates passkey** (biometric, security key, or phone).
4. Done — user signs into BareNOC with one passkey tap.

### C. End-user daily login (10 seconds)

1. Open `https://<host>` → **"Sign in with passkey"**.
2. Touch biometric / tap key → in.

### D. DIY (self-serve, wiki-guided)

Same flow, documented with screenshots in the knowledge base: first-run wizard → groups → app registration → invite. The wiki is the 10-minute guide.

### E. Recovery (designed before we sell it)

- **Recovery codes:** Pocket ID shows 10 one-time recovery codes at passkey enrollment — the quick-start card gains a line: *"Save your recovery codes."*
- **Admin reset:** a Pocket ID admin can reset any user's passkeys (locked-out user re-enrolls).
- **Vendor break-glass:** our provisioning passkey remains enrolled; local `admin` account remains a second fallback.
- These paths get a drill in the SAT (see §7).

### F. Device onboarding (Phase 2, BareNOC-driven)

1. Admin (passkey-authenticated) adds a device in BareNOC and assigns a device group.
2. BareNOC mirrors the group to Pocket ID (or reuses existing); device group membership is checked for every view/configure/act.
3. Agent-capable device enrolls its passkey → verified and live. SNMP gear keeps encrypted credentials — actions require a passkey-bound admin.
4. Revocation = disable device passkey / remove from group → immediate.

This is managed **inside BareNOC** (no Pocket ID admin needed for devices).

## 5. Backup / Restore Scope

- `/opt/barenoc/volumes/pocket-id/` joins the **Layer 1 app backup** (users, passkey credentials, client registrations).
- `backup_app.sh` includes it; safe-mode + apply restore drills cover it.
- Losing the Pocket ID volume = users must re-enroll passkeys (recovery codes still valid) — so backup inclusion is non-negotiable.

## 6. Security Notes

- PKCE + `state`/`nonce` on all flows; redirect URIs validated server-side.
- Pocket ID only reachable via nginx path prefix (no direct port exposure); UFW stays 443-only.
- Client secret stored in `.env` (600, gitignored, redacted in UI).
- OIDC callback logs nothing sensitive; audit records `auth_method=oidc` on login.
